# Реклама по странам и отдельно по РФ

## Главное решение

Нельзя проектировать рекламу как “один SDK навсегда”.

Нужен **рекламный слой с провайдерами**:
- `AdMobProvider` — глобальный рынок
- `YandexProvider` — РФ/СНГ fallback или primary
- `NoAdsProvider` — если реклама недоступна
- `AdsRouter` — выбирает провайдера по региону / store / remote config

## Практическая схема

### Вариант A — быстрый старт
- global release: AdMob
- РФ: Yandex / без рекламы
- прогресс в РФ пока локальный или ограниченный
- без обязательного social login

### Вариант B — полноценный запуск в РФ
- отдельный RU-контур backend
- primary database в РФ
- Yandex Mobile Ads как основной ad provider
- при необходимости отдельный store-канал
- cloud save и account link через RU-контур

## Как не делать

Не делать так:
- кнопка UI -> SDK callback -> сразу начислили награду
- provider hardcoded в screen
- reward logic внутри ad implementation

## Как делать

### Правильный поток
1. клиент просит у backend `rewardSession`
2. backend говорит, какой provider использовать
3. клиент показывает рекламу через выбранный provider
4. backend подтверждает награду
5. UI обновляется только после backend result

## Что важно для плохой сети

Так как в РФ мобильный интернет может быть нестабильным:
- не блокируй основной геймплей, если реклама не загрузилась
- показывай “реклама недоступна, попробуйте позже”
- логируй причины фейла отдельно:
  - no fill
  - timeout
  - no network
  - provider error
  - user cancelled

## Что делать с правом и хранением данных

Если ты реально собираешь личные данные пользователей из РФ и хочешь cloud save / login / social,
то безопаснее считать, что нужен **RU-контур хранения**.

Если к этому пока не готов — практичный MVP:
- в РФ не форсировать аккаунты
- guest + local save
- rewarded ads через local provider
- cloud-функции включить позже

## Итог

Правильная архитектура рекламы:
- не один SDK
- а `provider abstraction + backend reward session + remote config`

Правильная архитектура для РФ:
- либо **RU-контур**
- либо **урезанный MVP без чувствительных cloud-функций**
