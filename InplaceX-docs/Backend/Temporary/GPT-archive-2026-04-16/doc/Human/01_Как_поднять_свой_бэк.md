# Как поднимать свой бэк сначала

## Короткий ответ

Да, backend лучше поднимать **сразу**, но не как набор микросервисов.

Правильный старт для InplaceX:
- отдельный backend-репозиторий
- один deployable service
- PostgreSQL
- Redis
- REST + WebSocket
- modular monolith

## Почему так

Backend нужен не ради красоты, а ради конкретных вещей:
- не терять прогресс
- хранить аккаунты
- выдавать рекламные награды безопасно
- держать комнаты и матчи
- сделать честный PvP
- потом добавить турниры

## Что должен уметь backend в первой версии

### Обязательно
- guest auth
- access/refresh token
- player profile
- cloud save / progress
- app config
- reward session для рекламы
- выдача награды сервером
- создание комнаты
- join/leave room
- ready/start match
- submit turn
- match history

### Можно позже
- friends graph
- social
- полноценные турниры
- admin panel

## Как делать по этапам

### Этап 1. Локальный старт
Подними через Docker Compose:
- api
- postgres
- redis

### Этап 2. Маленький production
Один VPS / один small cloud instance:
- nginx/traefik
- api container
- postgres
- redis
- nightly backup

### Этап 3. Когда появится PvP
Добавь:
- websocket gateway
- rate limiting
- idempotency
- structured logs
- health endpoints

### Этап 4. Когда появится РФ и несколько игр
Тогда уже думай про:
- multi-game platform
- multi-region
- RU-контур
- workers/background jobs

## Почему не микросервисы

На старте они дадут минусы раньше плюсов:
- больше DevOps
- сложнее трассировка
- сложнее локальная разработка
- сложнее отладка Codex'ом
- медленнее первый результат

Тебе нужен **один сервер, но разбитый по модулям**.

## Финальное решение

Стартуй с backend **сразу**, но как:
- modular monolith
- separate repo
- PostgreSQL + Redis
- REST + WebSocket
- один production service
