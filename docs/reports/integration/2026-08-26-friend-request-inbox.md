# Заявки в друзья и аудит онлайн-среза

## Границы и исходное состояние

- Режим: Codex Chat, ручная интеграция, поддержка UX light.
- Запрос владельца: компактное представление одной заявки; одна кнопка со
  счётчиком и отдельный список для нескольких; проверить Samsung скриншотом.
- Ветка: `fix/friend-request-inbox-v1`, основана на `3d1df679` (PR #93),
  который содержит актуальный `develop` `b5a4d507` и проверенную конфигурацию
  тестовой сборки. Изменения PR #93 не переписаны.
- Основная грязная рабочая копия не изменялась. Автоматизация, её очередь,
  сторонние PR и production не менялись.

## UX-контракт и реализация

`FriendRequestInbox` — общий Compose-компонент двух входов: корня Social и
списка друзей. Использованы существующие Material3 и цветовые токены проекта;
новых зависимостей, графики и каталожных компонентов нет.

- 0 заявок: кнопка отсутствует; открытое окно показывает пустое состояние.
- 1 заявка: светлая компактная кнопка с именем, по нажатию отдельное окно.
- Несколько: одна кнопка со счётчиком, окно с `LazyColumn` и стабильными ключами.
- При принятии все кнопки принятия блокируются до ответа. Запись скрывается
  только после серверного успеха. Ошибка остаётся рядом с заявкой и допускает
  повтор. Закрытие не принимает/не отклоняет запросы.
- Список не закрывается при изменении количества. Успех защищён от повторного
  появления той же записи из устаревшего входного списка.
- Имена отделены от заголовка, длинные имена переносятся в подробностях;
  действия имеют высоту не меньше 48dp, светлые поверхности — явный тёмный текст.
- Сетевая логика и её санитизированное журналирование остаются в существующем
  `MirkoriPlatformRuntime`, API и модель дружбы не изменены.

Скриншоты реальной Samsung-установки проверены вручную до/после. Для 50 заявок
и увеличенного шрифта использованы только синтетические fixtures в androidTest.
Веб-превью и варианты дизайна не требуются для этого ограниченного native UI.
Навыки: aistudio-ux-design (контракт, состояния, визуальная проверка),
aistudio-integrator (границы, gates, сохранение и отчёт), aistudio-agent-core
(правила проекта), orchestrate-complex-task / execute-work-unit /
synthesize-task-results (учёт отдельных результатов и блокеров).

## Результат аудита: что потеряно, а что не доделано

1. **Код приватных приглашений и онлайн-матчей существует.** Адресные
   приглашения и выбор online-режима входят в `c05d26b3` / PR #69, дружба и
   заявки — `d2939e42` и `a05a8eb3`. Они присутствуют в актуальном develop.
   `OnlineRuntime`, `OnlineDuelClient`, `OnlineDuelScreen` соединены с
   серверными маршрутами и authoritative match service.
2. **На Samsung потеряна именно конфигурация APK.** Из старого установленного
   APK извлечён `BuildConfig`: `ONLINE_BASE_URL = ""`. `createOrNull`
   возвращает null для пустого адреса, поэтому раздел выводил offline-состояние.
   Новая тестовая сборка проходит конфигурационный gate и открывает online UI.
3. **Есть неинтегрированная работа.** PR #85 остаётся открытым, пять его
   коммитов не являются patch-equivalent develop. Например, передача
   `opponentProgress` в `OnlineDuelGameField` есть в этой ветке, но не в
   develop. Это не удалённый код; ветку нельзя считать уже выпущенной.
   Полностью сливать старую ветку без проверки пересечений с новыми gameplay
   правками нельзя. В этом срезе PR #85 не изменялся.
4. **Реальные ограничения разработки:** входящие заявки API ограничены
   `LIMIT 50` без курсора/total; окно показывает весь полученный список,
   но полный просмотр свыше 50 требует отдельной серверной пагинации.
   Provider push при полностью выгруженном приложении не реализован —
   используется polling живого процесса. Отклонение заявки не добавлялось:
   в текущем клиентском контракте есть только принятие.
5. **Живой backend не отсутствует.** Проверенный `/meta/release` сообщает
   `inplacex-backend-2026.08.10.1-native`, git SHA
   `c05d26b39d553baa55dc1f0807504bea070f7496`.
   Неверный для этого backend путь `/health/release` возвращает 404 и
   не является признаком неработающего онлайна.

## Передача и откат

UI готов для проверки владельцем на Samsung; интеграция требует PR/CI.
Серверный выпуск заблокирован до восстановления GitHub Actions billing и
успешного rerun. Следующий ответственный за этот gate — владелец аккаунта.
Нет миграций БД, смены подписи или destructive updates. Для отката сохранён
предыдущий установленный APK локально вне Git; вернуть его можно обновлением
без очистки данных. Скрытые/production тестовые аккаунты не создавались.

Полный сценарий более 50 заявок, полноценный push и интеграция PR #85 остаются
явными незакрытыми пунктами аудита, а не обещанием выполненной реализации.
