## Blocking findings

1. The validator still accepts a required Gradle command behind a successful short-circuit. Replacing `run: ./gradlew lint` in the complete workflow with `run: true || ./gradlew lint` exits `0` and reports `OK: CI workflow contract checks passed`.
2. `_contains_artifact_identity()` accepts any token containing `scripts/ci/artifact_identity.sh`. Replacing the real invocation with `echo bash scripts/ci/artifact_identity.sh` in the complete workflow exits `0`, so a label can impersonate signing evidence.
3. `_contains_avdmanager_create()` falls back to a raw-text regular expression. Replacing the real AVD creation with `echo "avdmanager create avd"` in the complete workflow exits `0`, so no emulator needs to be provisioned.
4. The bundled `fail_short_circuit`, `fail_artifact_static_signing` and `fail_emulator_noop` fixtures do not prove that these exact hostile mutations are rejected in an otherwise-valid full workflow.
5. `_has_bounded_boot_wait()` accepts comment-only tokens for `sys.boot_completed`, the bounded loop, `sleep 1` and `exit 1`. Removing `adb wait-for-device` also passes validation, while the real command is not wrapped in `timeout`.
6. Heredoc text is parsed as executable commands. A `cat <<'EOF'` block containing `./gradlew lint`, `:app:assembleRelease` or `:app:connectedDebugAndroidTest` passes without executing Gradle.
7. Short-circuited emulator, KVM and connected-test commands pass. The KVM guard also does not require read/write access to `/dev/kvm`.
8. The signing-script validator accepts `apksigner verify` and output names in comments. Negative fixtures pass on any incidental error instead of requiring the expected diagnostic category.
9. A GitHub Actions run for the exact candidate SHA was still in progress during review. Even a green run cannot compensate for the independently reproduced fail-open contract bypasses.
