## Проверка перед каждой сборкой или задачей

В локальном основном checkout и рабочей копии PR:

```powershell
git ls-remote automation refs/heads/develop
git fetch --no-write-fetch-head automation develop
git rev-parse automation/develop
git rev-list --left-right --count develop...automation/develop
git merge-base --is-ancestor automation/develop HEAD
git status --short --branch
```

На удалённом основном checkout те же команды выполняются с `origin`.

Начинать работу можно, когда живой опубликованный SHA совпадает с fetched-ref,
рабочий `develop` совпадает с ним, а текущий HEAD содержит эту основу.
У PR-ветки могут быть собственные новые коммиты поверх основы. При ошибке связи,
отсутствующем `develop`, расхождении или старой основе сборка останавливается.
Незакоммиченные изменения учитываются отдельно: один SHA не идентифицирует
сборку с изменёнными файлами. Для APK сохраняются SHA исходников, состояние WIP,
вариант сборки и SHA-256 самого артефакта.

Свежая дата локального коммита, название ветки и `versionName=1.0` не доказывают
свежесть основы. Android собирается на рабочем ПК; VPS используется как канал
доступа к удалённому ПК, сборка на нём не запускается.

## A03 — покупка энергии при полном запасе

Проверка свободного места, восстановления энергии и монет выполняется внутри
одной SQLite-транзакции вместе с покупкой. Полный запас возвращает отказ без
списания; две покупки последней единицы не могут обе списать монеты. Неположительное
количество отклоняется, большой запрос ограничивается свободным местом без overflow.
Остальные покупки и схема базы не менялись. В журнал попадает только исход операции.

Карточка энергии отключает действие в компактном и развёрнутом представлениях и
показывает «Энергия уже полная» / «Energy is full». Прошли семь существующих JVM-тестов
магазина, сборка app/test APK и по семь новых тестов реального хранилища на каждом
телефоне. Тесты используют отдельные UUID-базы и удаляют только их.

В обычном магазине на Redmi и OnePlus при `5/5` подтверждены отключённое действие,
локализованная причина и отсутствие списания после физического нажатия. Баланс
Redmi остался `9975`, OnePlus — `10000`. APK обоих устройств имеет SHA-256
`f65a4d339281c064d60d781699a5ae6de3bade0e972d97e0c74f36509acc6fab` и включает A02.
Данные приложения сохранены, шрифт — 1.0.

Luna реализовала A03 и исправила обнаруженные ошибки новых тестовых сценариев.
Для входа использованы точные связанные фрагменты исходников вместо всего каталога
переводов; лимит выбранного входа не увеличивался. Прежние ответы, ошибки компиляции
и ошибочный выбор дочернего accessibility-узла в host-проверке сохранены. Итоговая
проверка использует действующий узел кнопки и свежий уникальный dump. Резерв Sol
для A03 не потребовался. Очереди и паузы сохранены.

Успешный прогон хранилища на Redmi уточняет A19: проблема запуска тестовой UI Activity
остаётся открытой, но обычная instrumentation выполняет эти тесты. [Задача A03](tasks/INPX-AUDIT-A03-20261015.md).
## A04 — статистика онлайн-матчей

UI передаёт каждый успешно принятый серверный snapshot в отдельный учёт прогресса,
включая polling, восстановление сессии и ответы на отправку секрета/хода. Учёт
выполняется до очистки указателя завершённой сессии; профиль сразу получает новое
состояние. Транспорт, правила дуэли и награды остальных режимов сохраняются.

SQLite-схема `11 → 12` добавляет журнал `online_match_stat_receipts`. Запись старта,
терминального исхода и соответствующих счётчиков атомарна. Учитываются канонический
ID сессии и серверный победитель относительно клиента. Повторные, устаревшие и
одновременные ответы не добавляют второй результат. Нейтральный исход не становится
поражением; таймаут комнаты до начала игры не увеличивает число сыгранных матчей.
Логи содержат только фиксированный исход. До миграции сохранены приватные копии
баз/настроек вне Git и проверен прежний APK для восстановления.

На AiStudio прошли 20 JVM-тестов mapper/онлайн-клиента/логики экрана и сборка пары

12 тестов базы/миграций, включая полноценную миграцию v11 с сохранением прогресса,
кампании, sync queue и entitlement journal. Все тестовые базы изолированы.

## A05 — единая проверка Pro для авто-таблицы

Все пять режимов получают существующее право из effectiveProgressState. Входные
экранные значения по умолчанию запрещают доступ. Онлайн проверяет право отдельно
от сохранённого предпочтения и сразу применяет его к отображению, вводу, стиранию
и отправке. Снятие/возврат Pro сохраняет текущую сессию, историю и ручную работу.

Прошли 36 JVM-тестов, сборка app/test APK и на каждом телефоне один SQLite-тест
и один UI-тест с 40 сценариями. Пять production-экранов и семь состояний права
проверены в неэкспортируемом debug-экране с профилями и часами в памяти. По 15 снимков
каждого телефона записаны в отдельный каталог конкретного прогона. Покупки и права
игрока не изменялись. Обычные гостевые режимы и живой приватный матч также проверены:
PRO отключён, ручные отметки и ввод работают; три принятых хода дали победу Redmi.

Исходные записи A04 сохранены, холодный запуск не повторяет результат. Монеты,
энергия, уровень и рейтинг сохранены, игровые данные не очищались. Существующая
схема 12 и debug-подпись прежние. Новая foreground-передача MainActivity позволила
выполнить A05 UI на обоих телефонах; старый фоновый runner A19 этим не закрыт.
ID и накопленные квитанции сохранены, использованы два ограниченных резерва Sol;
очереди и paused-задачи не возобновлялись. Следующий пункт A06 не запускался.
