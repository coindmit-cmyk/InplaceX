## Проверка перед каждой сборкой или задачей

В локальном основном checkout и рабочей копии PR:

```powershell
git ls-remote automation refs/heads/develop
git fetch --no-write-fetch-head automation develop
git rev-parse automation/develop
git rev-list --left-right --count develop...automation/develop
git merge-base --is-ancestor automation/develop HEAD
git status --short --branch
```

На удалённом основном checkout те же команды выполняются с `origin`.

Начинать работу можно, когда живой опубликованный SHA совпадает с fetched-ref,
рабочий `develop` совпадает с ним, а текущий HEAD содержит эту основу.
У PR-ветки могут быть собственные новые коммиты поверх основы. При ошибке связи,
отсутствующем `develop`, расхождении или старой основе сборка останавливается.
Незакоммиченные изменения учитываются отдельно: один SHA не идентифицирует
сборку с изменёнными файлами. Для APK сохраняются SHA исходников, состояние WIP,
вариант сборки и SHA-256 самого артефакта.

Свежая дата локального коммита, название ветки и `versionName=1.0` не доказывают
свежесть основы. Android собирается на рабочем ПК; VPS используется как канал
доступа к удалённому ПК, сборка на нём не запускается.

## A02 — восстановление активной игры

`GameFieldScreen` теперь сохраняет данные своего `SavedStateHandle` через
`rememberSaveable` и существующую сериализацию состояния. Флаг учёта старта
матча восстанавливается вместе с игровой сессией. Новая сессия получает новое
состояние, в том числе при одинаковых параметрах. Текущие правила доступа к
авторежиму и отмена временных операций сохранены.

Тест использует реальный `GameFieldScreen` в отдельной debug Activity и
`ActivityScenario.recreate()`. Он вводит ход через отображаемые кнопки и
проверяет историю, счётчик, частичный ввод, отметку матрицы, секрет, прошедший
таймер и единственный старт. Дополнительная кнопка fixture проверяет новый матч.
Fixture не входит в release manifest и не открывает базу игрока.

На AiStudio прошли 27 выбранных JVM-тестов и сборка `globalDebug` app/test APK.
На OnePlus прошёл новый UI-тест. В обычной компании на обоих телефонах после
смены системного шрифта сохранились ход `0123`, счётчик `1/20` и остаток времени:
на Redmi `03:26 → 01:11`, на OnePlus `04:17 → 02:08`. Шрифт восстановлен к 1.0.
Прогон Redmi завершён host-timeout через 150 секунд без результатов assertions;
это остаётся открытым ограничением A19, а не PASS. Данные приложения не очищались.

На обоих телефонах установлен один APK с SHA-256
`bc69a9e29202989ab8b25b40a05267e9e85608822eef35c13795a011631b4632`.
APK собран на удалённом рабочем ПК и подписан локальным прежним debug-ключом
для установки поверх существующих данных. Ключ не передавался на удалённый ПК.

Luna выбрала контекст, затем повторно запрашивала уже предоставленный тест и
ещё не созданные выходные файлы. После её диагностики использован один резервный
